Forecasting Longitudinal Networks with lame

Cassy Dorff, Tosin Salau, Shahryar Minhas

2026-11-03

What this vignette covers

lame() with at least one dynamic component (dynamic_beta, dynamic_ab, dynamic_uv) gives you a state-space model that is exactly the right object for forecasting future periods. This vignette walks through:

  1. Fit a model with dynamic coefficients.
  2. Forecast h periods ahead on the link scale and the response scale.
  3. Compute counterfactual forecasts by feeding in alternative future covariates.
  4. Visualise the forecast and the per-coefficient ribbon plot.
  5. Diagnose whether the forecast variance has exploded (near- unit-root coefficients).

Step 1: Fit

We simulate 30 actors over 6 periods, a single dyadic covariate trade, and a directed binary outcome cooperation. The effect of trade on cooperation is time-varying and mean-reverting in the simulation: it follows an AR(1) around 0.5 with persistence 0.7, starting high (0.9) and settling toward its long-run level. The network is moderately dense (~37%). Even with many observed dyads, six periods provide limited information about temporal persistence. The chains below are short, to show the interface.

A note on data choice: dynamic_beta needs both a reasonable number of periods and enough ties per period to pin down a coefficient for that period. A sparse panel with only a few periods informs both the coefficient path and its persistence weakly. Step 5 examines the resulting uncertainty using the fitted posterior and forecast intervals.

library(lame)
set.seed(2026)

n_fc <- 30
T_fc <- 6
rho_true <- 0.7
beta_bar <- 0.5
beta_t_true <- numeric(T_fc)
beta_t_true[1] <- 0.9
for (t in 2:T_fc) {
    beta_t_true[t] <- beta_bar + rho_true * (beta_t_true[t - 1] - beta_bar) +
        rnorm(1, 0, 0.15)
}

Xdyad <- lapply(seq_len(T_fc), function(t) {
    x <- matrix(rnorm(n_fc * n_fc), n_fc, n_fc)
    array(
        x,
        dim = c(n_fc, n_fc, 1),
        dimnames = list(NULL, NULL, "trade")
    )
})
a_fc <- rnorm(n_fc, 0, 0.4)
b_fc <- rnorm(n_fc, 0, 0.4)
Y <- lapply(seq_len(T_fc), function(t) {
    eta <- -0.5 + beta_t_true[t] * Xdyad[[t]][, , 1] + outer(a_fc, b_fc, "+")
    Yt <- matrix(rbinom(n_fc * n_fc, 1, pnorm(eta)), n_fc, n_fc)
    diag(Yt) <- NA
    rownames(Yt) <- colnames(Yt) <- sprintf("a%02d", seq_len(n_fc))
    Yt
})
names(Y) <- paste0("t", seq_len(T_fc))

round(beta_t_true, 3) # simulated coefficient path
#> [1] 0.900 0.858 0.589 0.583 0.545 0.432
sapply(Y, function(y) round(mean(y, na.rm = TRUE), 3)) # per-period density
#>    t1    t2    t3    t4    t5    t6 
#> 0.400 0.374 0.378 0.367 0.352 0.357

fit <- lame(
    Y,
    Xdyad = Xdyad,
    family = "binary",
    R = 0,
    dynamic_beta = "dyad", # the trade coefficient is AR(1)
    dynamic_beta_kind = "ar1", # mean-reverting; switch to "rw1" for drift
    nscan = 150,
    burn = 30,
    odens = 5,
    verbose = FALSE
)

# estimated path of the trade coefficient
coef_path <- coef(fit)
trade_row <- grep("^trade[._]dyad$|trade", rownames(coef_path), value = TRUE)[1]
round(coef_path[trade_row, ], 3)
#>    t1    t2    t3    t4    t5    t6 
#> 0.896 0.812 0.593 0.507 0.511 0.490

Compare the estimated coefficients with the simulated path above. Step 5 also checks the upper posterior bound on \(\rho_\beta\): a short panel carries limited information about the persistence even when the process mean-reverts.

A quick diagnostic: summary(fit) prints the per-block posterior-mean ρ_β and fires a stationarity warning when, for any block, the 5th percentile of the posterior on ρ_β is ≥ 0.97 and the IQR is < 0.1 (i.e. at least 95% of the mass sits near a unit root with little spread). The forecast-time warning fires on a complementary trigger: the upper 97.5% credible bound on ρ_β reaches 0.99. If either warning fires, examine the persistence draws, chain diagnostics and forecast uncertainty. Use dynamic_beta_kind = "rw1" when permanent drift is an appropriate model: RW1 fixes the persistence at one and changes the forecast law.

The typical cell of fc_ci[[1]] carries an informative lower / median / upper triple – a genuine sub-interval of [0, 1] rather than the whole range, because the coefficient path is mean-reverting (the posterior mean of rho_beta is 0.85; Step 5 reports its upper bound). The heatmap shows the model does not forecast a uniform network: some sender/receiver pairs carry a much higher predicted tie probability than others, inherited from their estimated additive effects and the recovered trade coefficient. The horizon panel shows the average predicted probability staying roughly level (the coefficient is mean-reverting) while its credible band widens with h – the visual signature of accumulating forecast uncertainty.

The forecast propagates (β_t, a_t, b_t, U_t, V_t) forward by drawing from the joint posterior of the dynamic state-space hyperparameters (ρ_β, σ_β, ρ_ab, σ_ab, ρ_uv, σ_uv) for each posterior draw. The same forecasting machinery covers the supported outcome families; the binary example above is illustrative. For family = "normal", type = "response" returns the forecasted conditional mean. For family = "poisson", each matched parameter draw has conditional mean e * exp(η + ve / 2), where e is the future-period exposure (set with newexposure). With by_draw = FALSE the point forecast is the mean count at the draw-averaged predictor and variance, e * exp(mean(η) + mean(ve) / 2), the form of the in-sample fitted() value; by_draw = TRUE returns each draw’s own conditional mean. Use interval = "prediction" for predictive count quantiles, or interval = "credible" for quantiles of the per-draw conditional means. These are distinct summaries.

Poisson exposure offsets via period_exposure

For family = "poisson", pass period_exposure = e to lame() (a non-negative numeric vector of length T) when the per-period rate should be scaled by a known exposure (e.g. weeks observed, population size, number of edge-formation opportunities). The sampler treats log(period_exposure[t]) as a fixed offset on the linear predictor: conditional on the latent log-rate Z, the Poisson mean is period_exposure[t] * exp(Z_t). Integrating the Gaussian observation noise within a parameter draw gives period_exposure[t] * exp(η_t + ve / 2); at the posterior means of η_t and ve this is the mean count fitted() reports. Zero exposure gives a structural zero count. Setting a non-trivial (any value not equal to 1) period_exposure for a non-Poisson family is rejected with an error. When you call predict(fit, h = K) later without newexposure, the response-scale forecast reuses the last observed exposure for every future period; pass newexposure = rep(e_new, K) to forecast under a different exposure path.

Step 3: Counterfactual forecasts

Pass newdata = list_of_h_future_X_arrays to combine alternative future covariates with the forecast. Each array is n x n x p and the slice order along the 3rd dimension must match the original dimnames(Xdyad[[1]])[[3]] from the fit (here a single slice, trade).

# seed the forecast draws
set.seed(1)
# baseline: hold trade at its last observed value
last_X <- Xdyad[[length(Xdyad)]]
X_future <- list(last_X, last_X, last_X)
fc_cf <- predict(fit, h = 3, type = "response", newdata = X_future)

# counterfactual: one more unit (one standard deviation) of trade for every dyad
X_future_up <- lapply(X_future, function(x) {
    x[, , 1] <- x[, , 1] + 1
    x
})
fc_up <- predict(fit, h = 3, type = "response", newdata = X_future_up)

# change in each dyad's predicted probability at h = 3
delta_h3 <- fc_up[[3]] - fc_cf[[3]]
summary(as.vector(delta_h3))
#>     Min.  1st Qu.   Median     Mean  3rd Qu.     Max. 
#> 0.006484 0.095982 0.114325 0.107554 0.126730 0.141251

The trade coefficient is positive and mean-reverting, so a one-unit increase in trade raises the posterior-mean cooperation probability at h = 3 on average (the mean and median of delta_h3 are both positive). The per-dyad shift varies in size, and a minority of dyads even show a small negative shift: the three-step-ahead forecast of the coefficient is itself uncertain (its posterior at h = 3 is centred well above zero but has nonzero mass below it), and the marginal probit effect \(\phi(\eta)\,\beta\) is smallest for dyads whose baseline linear predictor \(\eta = a_i + b_j + \beta x_{ij}\) already sits far from the 0.5 probability boundary. For substantive interpretation, summarise delta_h3 for the dyads that matter rather than reporting the aggregate summary().

Two properties of counterfactual covariates. (1) Because dynamic_beta draws the coefficient path forward from its posterior, the same covariate change can produce different magnitudes at different horizons, because the multiplier on trade is itself uncertain and drifting. (2) Multiplicative counterfactuals on covariates that take negative or zero values (such as this centred trade covariate) do not make substantive sense; prefer additive shifts there, which is why we used + 1 rather than * 2 above.

Step 5: Forecast diagnostics

predict(fit, h = ...) fires a one-per-fit warning if the upper 97.5% credible bound on ρ_β reaches 0.99 (i.e. the posterior puts non-trivial mass near the unit root). For the fit above, that bound is 0.98; it is below the warning threshold. The simulated process mean-reverts, and the bound reports what this panel says about its persistence. The two transition models have different conditional forecast variances:

  • AR(1), dynamic_beta_kind = "ar1" with \(|\rho| < 1\): the conditional \(h\)-step variance of \(\beta_{T+h}\) given the training window is \(\sigma_\beta^2 \cdot (1 - \rho^{2h}) / (1 - \rho^2)\). It saturates (the increment from \(h\) to \(h+1\) shrinks geometrically to zero) and the limit is the stationary variance \(\sigma_\beta^2 / (1 - \rho^2)\). That stationary level itself blows up as \(\rho \to 1\), so AR(1) is still informative at long horizons only when \(\rho\) is comfortably bounded away from 1.
  • RW1, dynamic_beta_kind = "rw1": \(\rho = 1\) by construction and the \(h\)-step variance is exactly \(\sigma_\beta^2 \cdot h\), linear growth in \(h\), never saturating.

In words: AR(1) eventually forgets the training window and falls back to a stationary distribution; RW1 keeps adding innovation variance every period. AR(1) forecasts can stay tight for moderate \(h\) when \(\rho\) is small; RW1 forecasts get linearly wider every step regardless. When the AR(1) stationarity warning fires and the underlying process is genuinely unit-root, refit with dynamic_beta_kind = "rw1"; if the AR(1) posterior on \(\rho\) is near-but-not-at 1 and the science supports eventual mean reversion, assess AR(1) forecasts over the horizons supported by held-out validation. The warning printed by predict() states whichever of these two variance behaviours applies to your dynamic_beta_kind.

A sparse, short, drifting panel

We now simulate fewer actors, only four periods, single-digit tie density in the early periods, and a covariate effect that drifts upward instead of mean-reverting. There is no long-run level for the AR(1) to find in these four periods. The fitted persistence and forecast intervals show how the AR(1) model represents that uncertainty:

set.seed(2026)
n_sp <- 20
T_sp <- 4
beta_drift <- c(0.4, 0.9, 1.4, 1.9) # drifts upward without mean reversion
X_sp <- lapply(seq_len(T_sp), function(t) {
    x <- matrix(rnorm(n_sp * n_sp), n_sp, n_sp)
    array(
        x,
        dim = c(n_sp, n_sp, 1),
        dimnames = list(NULL, NULL, "sanction_risk")

})

The nscan = 100, burn = 25, odens = 5 settings inside lfo() are chosen so the vignette builds in well under a minute on a laptop. They give 100 / 5 = 20 stored draws per leave-out refit (burn-in is run and discarded, not subtracted from nscan). Compare the two reported leave-out scores directly. A sharp decline at the last origin can suggest a late change in the data-generating process, but short chains and predictive variability can also move a score. After checking those sources of uncertainty, detect_change_point(fit) can identify a coefficient path and period for closer inspection. Its tail ratio is a heuristic reference, not a formal test or a Bayes factor.

Probability-integral-transform (PIT) calibration

forecast_pit() complements lfo() by asking a sharper question: given the held-out outcomes, is the h-step posterior-predictive distribution itself well calibrated? The PIT uses the posterior predictive CDF, averaging the conditional distributions over matched posterior draws. For binary / Poisson / ordinal outcomes it randomises between the CDF just below and at the observation, using the Czado-Gneiting-Held PIT (Czado, Gneiting & Held 2009). A well-calibrated forecast produces PIT values that are Uniform(0, 1).

# fit on the first five periods, hold out the sixth
fit_train <- lame(
    Y[1:5],
    Xdyad = Xdyad[1:5],
    family = "binary",
    R = 0,
    dynamic_beta = "dyad",
    nscan = 100,
    burn = 30,
    odens = 5,
    verbose = FALSE
)
# seed the randomised PIT
set.seed(1)
pit <- forecast_pit(fit_train, y_future = list(Y[[6]]))
print(pit)
#> 
#> ── Forecast PIT calibration check ──
#> 
#> • Family: "binary"
#> • Forecast horizon: 1
#> • Held-out dyads: 870
#> • Kolmogorov-Smirnov statistic against Uniform(0, 1): 0.039
#> • Global calibration p-value: unavailable for dependent network cells
#> • Fraction in [0.025, 0.975]: 0.946 (expect 0.95)
#> These are descriptive diagnostics. Network dependence requires a calibrated
#> joint reference for global inference.

plot(pit) renders the PIT values against the Uniform(0, 1) reference that a perfectly calibrated forecast would follow:

plot(pit)

Bars that hug the uniform reference indicate a well-calibrated forecast. A U-shape (mass piling up in the tails) is the signature of an over-confident forecast whose intervals are too narrow; a central hump is the opposite, an under-confident forecast with intervals that are too wide. On this single binary held-out period the randomised PIT is noisy, so read the plot for gross departures rather than small wiggles, and corroborate it with cover_95 below.

fit_train has only five training periods. Its upper 97.5% posterior bound on \(\rho_\beta\) is 0.955, which is below the forecast warning threshold; a bound at the threshold means the forecast carries the unit-root variance described in Step 5.

pit$cover_95 is the fraction of PIT values in [0.025, 0.975]; here it is 0.946, compared with 0.95 under marginal calibration. For discrete outcomes this uses the randomised PIT and is not the coverage of a discrete outcome interval. The KS statistic describes the distance between the empirical PIT distribution and the uniform reference.

pit$ks_p is NA: dependent network cells require a calibrated joint reference for a global significance test. Neither the PIT fraction nor the descriptive KS statistic supplies such a test. For binary outcomes, randomisation adds variability as well, and this vignette shows one held-out period; several held-out periods and the forecast scores above give the comparison. The seed above makes this displayed randomisation reproducible.

Comparing two fits with loo_compare()

When you have two candidate specifications, say a static-beta baseline and a dynamic_beta = "dyad" variant, loo::loo_compare() is the one-liner that ranks them on out-of-sample predictive performance when their saved scores are valid observed likelihood factors. The following models explicitly set dcor = FALSE; estimated residual dyad correlation would require joint dyad factors. Both save the matched observed scores with save_log_lik = TRUE:

# two candidates with independent residuals and saved log-likelihoods
fit_static <- lame(
    Y,
    Xdyad = Xdyad,
    family = "binary",
    R = 0,
    dcor = FALSE,
    nscan = 5000,
    burn = 1000,
    odens = 25,
    save_log_lik = TRUE,
    verbose = FALSE
)
fit_dyn <- lame(
    Y,
    Xdyad = Xdyad,
    family = "binary",
    R = 0,
    dcor = FALSE,
    dynamic_beta = "dyad",
    nscan = 5000,
    burn = 1000,
    odens = 25,
    save_log_lik = TRUE,
    verbose = FALSE
)

# the best model has elpd_diff = 0; a named list labels the rows
cmp <- loo::loo_compare(list(
    fit_static = loo::loo(fit_static),
    fit_dyn = loo::loo(fit_dyn)
))
cmp
best <- rownames(cmp)[1]
runnerup <- rownames(cmp)[2]
diff_val <- abs(round(cmp[2, "elpd_diff"], 1))
se_val <- round(cmp[2, "se_diff"], 1)
ratio <- round(diff_val / se_val, 1)

How to read this output. The top row is the preferred model and has elpd_diff = 0. Each subsequent row gives the difference in expected log pointwise predictive density relative to that model and the standard error of the difference. A difference that is large relative to its standard error supports the preferred model; when the two are similar, the specifications are not distinguishable on this predictive criterion. The Pareto-\(k\) diagnostics in the loo output report which pointwise estimates are reliable.

These binary models store probit observed-cell likelihood factors and use independent residuals. normal, binary, poisson, and explicit-cutpoint ordinal models support observed marginal scores; Poisson scores use adaptive numerical integration with an accuracy check. A correct marginal score becomes a LOO factor only when the saved factorization contract supports it. Symmetric fits use each unordered dyad once; directed fits with estimated or nonzero residual correlation are refused by LOO/WAIC until joint dyad factors are supplied.

Capped binary, fixed-rank nomination and data-induced ordinal models do not supply an exact observed score through the current dispatcher. An explicit log_lik_method = "observed_ghk" request provides the documented legacy approximate diagnostic for those models; "augmented" provides a latent-Z diagnostic. Neither is accepted by LOO/WAIC. Use held-out evaluation appropriate to the fitted rank/cap model, rather than treating a diagnostic as its likelihood.

Memory-conscious long runs

If the in-memory log-likelihood matrix from save_log_lik = TRUE would exceed RAM, pass save_log_lik = "chunked" instead. The on-disk chunks are read by loo() when the same observed-factor contract passes. read_log_lik(fit) also reads marginal or diagnostic scores that cannot be used for LOO/WAIC:

fit_chk <- lame(
    Y,
    Xdyad = Xdyad,
    family = "binary",
    R = 0,
    dcor = FALSE,
    dynamic_beta = "dyad",
    nscan = 2000,
    burn = 500,
    odens = 5,
    save_log_lik = "chunked", # binary files, one per chunk of columns
    log_lik_chunk_size = 5000L,
    verbose = FALSE
)
loo::loo(fit_chk) # reads the chunks transparently
